# Studio 系统集成

本仓库供合作平台开发者接入 Studio。文档目标版本为 **0.13.1（联调预发布）**；实际部署状态以 `deployment.json` 为准，正式验收后再发布 1.0.0。

0.13.1 修复双人字幕开头漏字被误归到上一轮台词而中止制作的问题；补字沿用同轮真实语音锚点，不增加模型请求。参数、响应及调用示例无需调整，随视频 Worker 部署后对新渲染生效，历史任务不自动重做。

0.13.0 的个人配音按完整成品时长结算，超出预占时在原任务补足余额后恢复，不重复购买。0.12.0 兼容新增个人 Key 录音识别，与生图、配音共用原钱包和日限额，旧 Key 需明确授权。相关 API、Worker、前端及迁移共同部署后生效。

0.11.5 为合格的第三家生图供应商预留累计采购预算，新报价冻结采购单价上限及报价当时的较低任务预算；调高后台预算不会扩大旧报价。共享并发128、每供应商最多采购一次、单张只结算一次和客户价格保持，接入方无需修改参数。实际启用供应商须完成对应账户、协议和画幅核价，并共同部署API、Worker及运营配置。

0.11.4 的新生图任务对同一供应商最多发起一次新采购，故障切换不再通过其他型号重复采购同一家。共享生图执行容量统一128，单个视频仍按原有 `image_concurrency` 设置执行；账户按逻辑图片任务计数，未知采购保留费用敞口，同一图片可以切换其他供应商。图片仍只结算一次，原结果查询与下载继续恢复；已受理任务保留原通道及预算，无需接入方修改参数。须API、Worker和运营配置共同更新后生效。

0.11.2 修复共享生图实际并发及图片诊断缺漏；沿用现有请求和响应，已受理任务的通道及预算保持。运行时和容量配置共同发布后生效。

0.11.0 兼容新增百炼Flash配音目录，完整音轨基础价¥0.02/分钟，最少一分钟、30秒四舍五入；通过既有`voice_ids`选择，仍由视频统一结算。仅新选该服务的任务生效，已受理任务保留原价格。详见[变更记录](CHANGELOG.md)。

0.10.0 的 Studio 生图目录统一为 GPT-Image，默认每张 3 点真气；默认 ID 和请求字段保持，旧的已知选择自动归并。新图片与 GPT-Image API-Key 共用兜底、采购和限流，YI 不再承接新采购。图片仍由视频任务结算，旧报价、原任务及机构钱包归属保持。详见[变更记录](CHANGELOG.md)。

## 联调顺序

1. 双方确认机构编号、平台编号、用户标识及授权回调地址，通过单独渠道交接机构 API Key 和 SSO 换码凭证。
2. 使用专门开通的联调机构及独立密钥，先查询能力和余额，确认可用配置。
3. 按文档跑通脚本生成、审阅、视频提交、轮询和下载。
4. 验证重复提交、请求超时、身份隔离、凭证撤销、额度不足及链接过期。
5. 双方确认验收结果和正式切换时间，再启用正式机构凭证。

联调机构与生产机构应使用不同密钥。本文没有另设沙箱域名；使用正式环境执行真实生成时，按实际任务记录消耗。独立测试环境须由双方另行确认，不使用虚构地址。

## 版本与问题反馈

对接时记录双方确认的 Release/Tag，阅读该版本的文档。`main` 的 `deployment.json` 标明最新同步状态；`pending` 表示文档已准备、尚未确认对应部署。以成功部署后的 Release 为版本发布凭据。

从 0.8.3 起，可靠音稿的画面切换可分级回退并标记，生图明确拒绝按原因处理，具备有效检查点的图片任务在确认停机后保留原预占供继续制作。接入方继续查询原任务，无新增恢复接口或数据库迁移；已确认图片数量、顺序和计费快照保持，未知结果不自动重购。0.8.4 同步发布说明与版本标识，不新增接口或运行行为。详见 [接口变更记录](CHANGELOG.md) 与机构 API 的状态说明。

通过 Issues 提交接口问题，附接口路径、版本、HTTP 状态、错误码、任务 ID 和脱敏后的请求。凭证、客户资料、原始内容和商务约定通过双方约定的渠道单独交接。

本仓库由提供方的发布流程同步维护。文档修改建议通过 Issue 提交，维护者在源文档中修改并发布，确保说明、接口契约与部署版本对应。

## 共享执行容量与全站预算

单个制作任务继续使用既有 `image_concurrency` 的1、3、5或全部选项；多个用户共用执行容量，超过当前可用执行位或采购通道容量时排队。扩容不会改变请求字段、个人限额、原报价或一次结算规则。

Studio 的文字、语音等 AI 调用与平台生图采购共同受既有全站 AI 日预算约束；平台 API-Key 图片同样计入。共享图片按已确认采购费用或尚未确认的采购预留统计，不重复写入原成本账。原图恢复与结果查询不发起新采购时不会再次预留，用户仍按原任务结算。

0.11.3 的新图片处理期限为20分钟，排队也计入；既有已受理请求保持原截止。客户端应留交付余量，参考等待1300秒；超时后继续查询原任务，不创建重复采购。账户与通道容量仍由多人共享，扩容不改变每任务1/3/5/all和计价规则。
